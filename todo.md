# TODO: живой голосовой режим в вебе

Цель: голосовой режим в web_morda работает почти в реальном времени,
звучит естественно (не роботом), и можно перебить ответ голосом — модель
останавливается, слушает и отталкивается от нового сообщения. Финально —
режим без кнопки микрофона: один "шарик", который сам слушает и сам
отвечает, как Advanced Voice Mode у ChatGPT.

Порядок ниже — по возрастанию сложности и с учётом того, что каждый шаг
имеет смысл сам по себе (не обязательно доводить до конца, чтобы что-то
уже улучшилось).

## 1. Потоковый TTS в вебе (самый дешёвый и самый заметный выигрыш)

Сейчас `POST /api/v1/speak` синтезирует ВЕСЬ ответ одним блокирующим
вызовом (`ui/audio.py:synthesize_speech`) — веб ждёт полный текст +
полный синтез, тогда как терминал (`ui/audio.py:SpeechStreamer`) уже
умеет синтезировать по предложениям параллельно с генерацией и
воспроизведением.

- [ ] Завести WS-эндпоинт (или отдельные сообщения поверх уже
      существующего `/ws/chat`) для потоковой отдачи аудио по кускам —
      сервер шлёт WAV/PCM-чанк на каждое законченное предложение вместо
      одного финального файла.
- [ ] На бэкенде переиспользовать `SpeechStreamer`'s идею (два воркера —
      синтез N+1, пока играет N) вместо одного `synthesize_speech(text)`
      на весь ответ.
- [ ] На фронте — проигрывать чанки по мере прихода (`MediaSource`
      Extensions или последовательная очередь `<audio>`/`AudioBufferSourceNode`),
      не ждать полный blob.

## 2. Подбор скорости под железо

- [ ] Проверить `voice_chat_model=qwen3:4b` или `qwen2.5:3b` вместо
      дефолтного `qwen3:8b` — компромисс глубина/скорость, но в голосовом
      режиме и так действует правило "1-3 предложения", глубина не так
      важна.
- [ ] Проверить `stt_model` меньше `medium` (`small`/`base`) —
      faster-whisper, дефолт в `settings.py`. Точность распознавания
      просядет, но задержка до первого токена LLM уменьшится.
- [ ] Замерить реальный вклад каждого шага (STT / LLM / TTS) в общую
      задержку одного голосового хода — сейчас есть только ощущение "TTS
      самый медленный" (RTF ~4-5 у Chatterbox на CPU), не измеренные
      цифры по этой конкретной машине.

## 3. Более живой голос (вздохи, естественная подача)

- [ ] Chatterbox не вставляет паралингвистику (вздохи/смех) по тегам из
      текста — только настройки exaggeration/cfg_weight на общую
      экспрессивность. Попробовать покрутить их для более "живой" подачи
      без смены движка.
- [ ] Оценить Dia (Nari Labs) — умеет `(sighs)`/`(laughs)`/`(clears
      throat)` прямо из текста, НО тяжелее Chatterbox: проверить, влезает
      ли рядом с уже загруженной LLM в 5.9 ГБ VRAM (RTX 4050 Laptop) без
      постоянного выгружения моделей друг за другом.
- [ ] Дешёвая промежуточная мера без смены движка: разрешить
      `_VOICE_SYSTEM_PROMPT` (mcp_agent/prompts.py) чуть более
      разговорную подачу (короткие "хм", "так", естественные паузы через
      пунктуацию) — не настоящие вздохи, но дешевле.

## 4. Барж-ин: перебить голосом, ход останавливается и слушает заново

Фундамент уже есть — кнопка "стоп" (`{"type":"stop"}`) и
мид-терн-инъекция сообщений, оба сделаны в этой сессии для веб-чата.

- [ ] Голосовой режим держит микрофон включённым постоянно (не по клику),
      пока активен voice-режим.
- [ ] Локальный VAD (voice activity detection) поверх уже существующего
      `AnalyserNode` (используется в `features/record-voice` для
      волны) — детектирует начало речи пользователя в любой момент, не
      только когда ждём ввод.
- [ ] Как только VAD видит начало речи:
      - если сейчас играет TTS-озвучка ответа — сразу поставить её на
        паузу локально (`<audio>.pause()`), без похода на сервер;
      - если ход ещё генерируется на сервере — отправить
        `{"type":"stop"}` (уже реализовано).
- [ ] После окончания речи пользователя (VAD видит тишину) —
      транскрибировать и отправить как обычное сообщение — попадёт в
      `inbound`/`mid_turn_queue` как уже устроено.

## 5. Полностью автоматический голосовой режим ("орбита")

- [ ] Отдельный полноэкранный UI-режим без кнопки микрофона — один
      `VoiceOrb` (уже есть, из этой сессии) на весь экран.
- [ ] Цикл "слушаю → распознал → отправил → жду ответ → озвучил →
      слушаю" полностью автоматический, без единого клика — VAD из
      пункта 4 решает старт/конец фразы сам.
- [ ] Явная кнопка "выйти из голосового режима" — иначе не с чем
      сравнить, когда пользователь ХОЧЕТ вернуться к обычному чату.

## Общий компромисс

Все три оси (быстрее / живее / умеет перебивать) упираются в одно и то
же CPU/VRAM железо — выигрыш по одной оси почти всегда означает уступку
по другой (более лёгкая модель — меньше "ума" в короткой реплике; более
живой TTS-движок — либо медленнее, либо не влезает в VRAM рядом с LLM).
Двигаться по пунктам 1→5 по порядку, замеряя на каждом шаге, стало ли
реально лучше на этой конкретной машине, а не только в теории.
