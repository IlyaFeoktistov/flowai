# Плагины

Расширяют flowAI без правки самого репозитория: новые слэш-команды, новые
тулы для модели (свой MCP-сервер) и хуки на события (после правки файла,
перед git-коммитом). Реализация: `src/mcp_agent/plugins.py` (загрузчик) и
`src/mcp_agent/plugin_hooks.py` (хуки).

Два независимых уровня:

1. **Глобальные плагины** — `plugins/<name>/plugin.json` в корне
   репозитория flowAI. Полноценный формат (манифест, версия, все три
   механизма разом), думать заранее про совместимость.
2. **Скилы и хуки конкретного проекта** — `.flowai/skills/`/
   `.flowai/hooks/` внутри ОТКРЫТОГО ПРОЕКТА (репозитория, с которым вы
   сейчас работаете через flowai, а не самого flowai). Без манифеста —
   просто файл, для одноразовых нужд именно этого проекта.

Из более широкого списка возможностей (Skills/Agents/Hooks/MCP/LSP/
Monitors/темы/PATH-бинарники/дефолтные настройки) в этой версии
реализованы три: пакет-формат + слэш-команды, MCP-серверы, hooks.
Остальное — предмет отдельного обсуждения.

## 1. Глобальные плагины

`plugins/` — папка в корне flowAI, видна сразу после клонирования
(держится в git пустой, через `.gitkeep`), но всё, что вы туда положите,
git игнорирует (см. `.gitignore`) — свои плагины не попадут в git-историю
самого flowAI.

Никакого шага "установки": положили папку — плагин подхватится на
следующем запуске flowai. Никакого реестра/сборки.

- **Включить/выключить** без удаления — положить/убрать пустой файл
  `.disabled` внутри папки плагина.
- **Обновить** — переписать файлы плагина, перезапустить flowai.
- Обнаружение кешируется на весь процесс — плагины не подхватываются на
  лету посреди сессии.
- Одна плохая манифест-запись, один плагин, у которого не импортируется
  модуль — не валит весь flowai и не мешает загрузиться другим плагинам.

### Формат `plugin.json`

```json
{
  "name": "example",
  "version": "0.1.0",
  "description": "Необязательное описание для /plugin",
  "commands": {
    "hello": {"module": "hello.py", "function": "run", "help": "say hello"}
  },
  "mcp_servers": {
    "example": {"command": "python3", "args": ["server.py"]}
  },
  "hooks": {
    "post_file_edit": ["hooks.py:on_edit"],
    "pre_commit": ["hooks.py:on_commit"]
  }
}
```

- `name` — **обязано совпадать** с именем папки плагина.
- `commands`/`mcp_servers`/`hooks` — все три опциональны.
- Пути (`module`, элементы `args`) резолвятся относительно папки плагина,
  если такой файл там существует; иначе передаются как есть.

## 2. Скилы и хуки конкретного проекта — `.flowai/`

Для одноразовой нужды в РАМКАХ КОНКРЕТНОГО проекта (не для распространения
как отдельный плагин) — положите файлы прямо в проект, который вы открыли
через flowai:

```
your-project/
└── .flowai/
    ├── skills/
    │   └── deploy.py       → команда /deploy в этом проекте
    └── hooks/
        └── checks.py       → post_file_edit и/или pre_commit
```

Никакого манифеста. **Скил** — любой `.py`-файл в `.flowai/skills/`,
имя файла (без `.py`) становится именем команды:

```python
# .flowai/skills/deploy.py
def run(args: str, console) -> None:
    console.print(f"[bold]Деплой: {args}[/]")
```

**Хук** — любой `.py`-файл в `.flowai/hooks/`, где ищутся функции с
именами `post_file_edit`/`pre_commit` (можно обе в одном файле, можно
только нужную):

```python
# .flowai/hooks/checks.py
def post_file_edit(path: str, repo_path: str) -> None:
    ...

def pre_commit(command: str, repo_path: str) -> str | None:
    return None  # непустая строка — блокирует коммит с этой причиной
```

Скил этого проекта **перекрывает** глобальный плагин с тем же именем
команды (более специфичный выигрывает) — но ни то, ни другое не может
перекрыть встроенную команду flowai (`/help`, `/clear`, ...). Хуки не
конфликтуют — если хук объявлен и глобальным плагином, и файлом в
`.flowai/hooks/`, вызываются оба.

Не кешируется между вызовами (в отличие от глобальных плагинов) —
`repo_path` меняется между проектами/сессиями чаще, чем стоит городить
кеш под это; сканирование пары небольших папок дешёвое.

## Слэш-команды (оба уровня)

```python
def run(args: str, console) -> None:
    """args — текст после "/hello ". console — тот же Rich-консоль,
    через который печатает всё остальное приложение (ui/console.py)."""
    console.print(f"[bold cyan]Привет, {args or 'мир'}![/]")
```

Функция может быть `async def` — `cli.py` дожидается результата только
если он awaitable. `/plugin` без аргументов — список установленных
глобальных плагинов И скилов/хуков текущего проекта.

## MCP-серверы (новые тулы для модели) — только глобальные плагины

```python
# server.py
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("example")

@mcp.tool()
async def my_plugin_tool(text: str) -> str:
    """Description for the model — English only."""
    return f"echo: {text}"

if __name__ == "__main__":
    mcp.run()
```

`.flowai/` пока не поддерживает per-project MCP-серверы — только
скилы и хуки.

`build_mcp_connections()` (`mcp_agent/config.py`) домешивает серверы
глобальных плагинов в тот же словарь, что и встроенные — тот же механизм
запуска подпроцесса. Совпадение имени сервера со встроенным — встроенный
побеждает, плагин пропускается с предупреждением.

`"command": "python3"`/`"python"` в манифесте резолвится в
`sys.executable` — **интерпретатор самого flowai**, а не первый `python3`
из `$PATH` — плагин не обязан знать про venv flowai.

**Видимость тулов пайплайну.** Роли пайплайна (Analyzer/Planner/Coder/
Verifier, см. [architecture.md](architecture.md)) получают тулы через
статичные списки имён в `roles.py`, которые физически не могут знать имя
тула из плагина заранее. `agent_builder.py` отдельно отслеживает, какие
загруженные тулы пришли с сервера плагина, и подмешивает их имена в
допущенный список на этапе фильтрации — плагинский тул автоматически
доступен **любой** роли, а не только той, что угадала его имя. То же
самое для `settings.optimized_tools` (урезанный список тулов).

## Hooks — оба уровня, вызываются вместе

```python
def on_edit(path: str, repo_path: str) -> None:
    """После успешного write_file/edit_file. Best-effort — если хук
    упадёт, сама правка всё равно считается успешной."""
    ...

def on_commit(command: str, repo_path: str) -> str | None:
    """Перед bash-вызовом, начинающимся с `git commit`. Непустая строка —
    блокирует коммит с этой строкой как причиной."""
    return None
```

Оба могут быть `async def`. В отличие от команд, у хуков нет "первый
победил" — вызываются **все** хуки данного вида: и от каждого глобального
плагина, и от `.flowai/hooks/` текущего проекта.

Реализация — `mcp_agent/plugin_hooks.py:PluginHookMiddleware`, подключена
в общий middleware-стек (`agent_builder.py:_base_agent_middleware`) — то
есть действует и в новом пайплайне (любая роль), и в легаси-агенте.

`pre_commit` триггерится только по ПЕРВОМУ сегменту команды до `&&`/`;`/`|`
— хук не может проверить коммит, который ему не показали.

## Рабочий пример

`examples/plugins/hello-world/` в репозитории — все три механизма разом
(команда, MCP-тул, оба хука), проверен вживую. Установить:

```bash
cp -r examples/plugins/hello-world plugins/hello-world
```

Перезапустить flowai, `/plugin` покажет `hello-world` в списке.
