# D&D-режим

`/dnd` переключает flowAI из режима "агент, помогающий с кодом" в режим
"мастер настольной ролевой игры" — изолированный агент, отдельный от
основного пайплайна (Router→Analyzer→Planner→Coder→Verifier). Реализация:
`src/mcp_agent/dnd_agent.py` (сам агент), `src/mcp_agent/dnd_tools.py`
(тулы: инвентарь, броски, факты, ...), `src/mcp_agent/dnd_store.py`
(SQLite-хранилище состояния игры).

## Почему отдельный агент, а не ещё одна роль пайплайна

D&D — не часть кодинг-пайплайна: не должен ни тянуть 40+ MCP-тулов
основного пайплайна, ни проходить `roles.py`'s approval-логику. Собран
по тому же рецепту, что `router.py:answer_casual` уже применяет для
простых ответов без тула — `create_agent(model, tools, system_prompt=,
middleware=[], checkpointer=InMemorySaver())` +
`mcp_agent/stage_runner.py:run_stage`, без единого прохода через
`agent_builder.py:_build_agent`/`_get_role_agent`.

`dnd_stream_chat(messages, game_id, on_event=None)` — тот же контракт
(async-генератор, те же типы событий: `answer_start`/`chunk`/`end`,
`tool_start`/`end`, `stats`, `done`), что и
`pipeline.py:stream_chat`/`agent.py:stream_chat` — `cli.py` вызывает его
так же, просто с дополнительным позиционным `game_id`.

Агент кешируется **по игре** (`game_id`) — у каждой игры свой набор
тулов (`build_dnd_tools` замыкает `game_id`), поэтому нельзя держать
один агент на процесс, как для casual-агента. Кеш — `BuildCache`,
freshness-ключ — `chat_model` (смена модели в `/settings` подхватывается
на следующий ход этой же игры).

## Команды

- `/dnd new [название]` — новая игра, мастер сам начинает (пишет
  вступление и спрашивает про расу персонажа) — синтетическая
  затравка-сообщение не эхается пользователю как "You ›".
- `/dnd <id>` — продолжить сохранённую игру (список — голое `/dnd`).
- `/dnd exit` — выйти из режима (доступно только внутри активной игры).
- `/dnd help` — команды режима.
- `/inventory`, `/status`, `/facts` — доступны только пока активна игра
  (`_dnd_active`); показывают инвентарь, статус персонажа (раса, класс,
  локация, календарь/время, погода, здоровье, кто рядом) и факты, которые
  мастер запомнил (обещания, секреты, лор мира).

Внутри режима игрок просто пишет обычным текстом, что делает персонаж —
мастер сам спрашивает, если что-то нужно уточнить.

## Состояние игры (`dnd_store.py`, SQLite)

Таблицы: `dnd_games` (имя, персонаж, локация, календарь, погода,
уровень/XP, золото, текущая угроза, здоровье), `dnd_inventory`
(предметы, экипировка), `dnd_party` (спутники), `dnd_facts` (память
мастера — компактится при накоплении, `compact_facts`), `dnd_injuries`
(травмы, лечатся отдельно от общего здоровья).

Функции — прямые CRUD-операции без ORM: `create_game`/`get_game`/
`set_character`/`update_location`/`update_calendar`/`update_weather`/
`add_xp`/`set_current_threat`/`add_inventory_item`/`equip_item`/
`add_party_member`/`remember_fact`/`add_injury` и т.д. — модель меняет
состояние игры через тулы `dnd_tools.py`, каждый тул — тонкая обёртка
над одной из этих функций.

## Механики

- **Проверки/броски** (`dnd_tools.py:_check_probability`,
  `_roll_xp_gain`) — вероятность успеха и награда XP зависят от разницы
  между уровнем персонажа и уровнем задачи.
- **Уровни/XP** (`dnd_store.py:xp_for_level`/`level_for_xp`/`add_xp`) —
  таблица прогрессии, добавление XP автоматически пересчитывает уровень.

## Мидлвари только этого агента

- **`_StopAfterQuestionMiddleware`** — если ответ мастера заканчивается
  вопросом к игроку И в том же ответе был вызван тул (например,
  "представляю врага" + `dnd_set_current_threat`), ReAct-луп даёт
  модели ещё один шаг генерации после результата тула — без защиты
  модель на этом шаге может начать рассказывать, как будто игрок уже
  ответил, хотя он ничего не написал. Инструкция в системном промпте
  одна не надёжна (модель может её просто игнорировать) — механическая
  подпорка: `awrap_tool_call` помечает результат тула сентинел-маркером,
  если вызвавшее его сообщение оканчивалось вопросом; `awrap_model_call`
  видит маркер и обрывает ReAct-луп немедленно, без единого лишнего
  токена нарратива.
- Бюджет шагов графа — `DND_RECURSION_LIMIT = 80` (не привязан к
  бюджетам ролей пайплайна напрямую, но того же порядка) — character
  creation легко тратит 11+ вызовов тулов ещё до того, как мастер
  начинает вступительную сцену.

## Выход из режима

`/dnd exit`, либо Ctrl+C когда мастер молчит (во время генерации
ответа Ctrl+C останавливает только сам ответ, не выходит из режима).
