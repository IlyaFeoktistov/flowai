# Команды

Полный список встроенных слэш-команд (`src/cli.py`). `/help` в UI
показывает тот же список.

Запуск из шелла: `flowai` — терминальный UI в текущей папке;
`flowai web [папка] [--port N] [--host H] [--rebuild] [--no-build]` —
веб-интерфейс с этой папкой как текущим проектом (см. [web-ui.md](web-ui.md#запуск)).

| Команда | Описание |
|---|---|
| `/help`, `/?` | эта справка |
| `/clear` | очистить историю ТЕКУЩЕЙ сессии (в памяти, ничего на диске) |
| `/clean [logs\|trash\|snapshots\|projects\|all]` | почистить накопившийся за всё время хлам — без аргумента только отчёт, ничего не удаляет (см. [persistence.md](persistence.md)) |
| `/settings` | настройки моделей и GPU; «параметры модели» — temperature/top_p/top_k/min_p/repeat_penalty/repeat_last_n/num_predict/num_ctx/no_mmap отдельно для каждой модели (см. [models.md](models.md)) |
| `/memory` | что помнит нейронка о пользователе/проекте, точечное/полное удаление |
| `/usage` | статистика токенов |
| `/instances` | список загруженных моделей по бэкендам (Ollama / llama.cpp): модель, RAM, VRAM; стрелками выбрать, Enter — выгрузить |
| `/doctor` | проверка Ollama/модели/MCP-серверов/хранилища, сколько инстансов моделей резидентно и сколько каждый занимает |
| `/reindex [путь ...]` | вручную собрать индекс для семантического поиска по коду разом — без аргументов весь проект, с аргументами только эти файлы/папки; НЕ единственный способ индекс наполнить — каждый `read_file`/`write_file`/`edit_file` тихо обновляет его в фоне сам по себе (см. [tools-and-mcp-servers.md](tools-and-mcp-servers.md)) |
| `/update` | проверить и подтянуть обновления flowAI из git |
| `/paste` | картинка из буфера обмена → плейсхолдер `[Image-N]` |
| `/img путь.jpg` | картинка с диска → `[Image-N]` |
| `/gen промпт` | сгенерировать картинку напрямую |
| `/music промпт` | потоковая генерация музыки, повторный `/music` или Ctrl+C — стоп |
| `/music_gen промпт` | один трек напрямую, без агента |
| `/gen_model промпт [--rig] [--raw] [--lod N]` | 3D-модель (см. [generative-features.md](generative-features.md)) |
| `/anim описание` | оживить риггованную модель (Animato) |
| `/gen_texture @модель @картинка` | перегенерировать текстуру по референсу |
| `/talk текст` | озвучить текст напрямую, без модели |
| `/dnd`, `/dnd new`, `/dnd <id>`, `/dnd exit`, `/dnd help` | D&D-режим (см. [dnd-mode.md](dnd-mode.md)) |
| `/inventory`, `/status`, `/facts` | только внутри активной D&D-игры |
| `/plugin` | список установленных плагинов/скилов/хуков и что каждый даёт (см. [plugins.md](plugins.md)) |
| `/plan [задача]` | режим план (или Shift+Tab): исследование только на чтение, план — по просьбе, правки заблокированы — см. «plan / build» ниже |
| `/build [файл плана] [уточнения]` | режим build; выполняет свежий план этой сессии или указанный файл из `.flowai/plans/` |
| `/<имя скилла> [аргументы]` | запустить скилл `SKILL.md` (из `.flowai/skills/` проекта или `~/.flowai/skills/`) — его инструкции уходят модели как задача хода; работает и в вебе, там же слеш-меню с подсказкой при вводе `/` (см. [plugins.md](plugins.md#скиллы-skillmd), [web-ui.md](web-ui.md#слеш-меню-в-инпуте--как-попап-команд-в-cli)) |
| `!команда` | выполнить shell-команду, вывод сразу уйдёт нейронке |
| `@имя_файла` | поиск файлов в текущей директории (автокомплит по имени/пути); при отправке сообщения содержимое реального файла вкладывается целиком, прямо на месте упоминания (см. `ui/at_mentions.py`) — не файл (email, `@ник`) остаётся как обычный текст |

Горячие клавиши: `Alt+V` — вставить картинку из буфера, `Alt+R` —
голосовой ввод (Ctrl+C — стоп записи), `Ctrl+C` во время ответа/музыки —
остановить генерацию.

## Как встроенные команды соотносятся с плагинными

Порядок разрешения в `cli.py`: сначала проверяются встроенные команды
(таблица выше, статичный список `if cmd == "/..."`), и только если
введённая команда не совпала ни с одной из них — идёт поиск среди
команд плагинов/скилов (`plugins.load_commands(os.getcwd())`).

Значит: **встроенная команда всегда выигрывает** — плагин/скил не может
переопределить `/help`, `/clear` и т.д., даже если назовёт свою команду
так же. Между собой скил текущего проекта (`.flowai/skills/`)
перекрывает глобальный плагин с тем же именем — подробности и почему
именно так в [plugins.md](plugins.md).

`/plugin` без аргументов — список установленных плагинов и что каждый
даёт (команды/MCP-серверы/хуки), включает и глобальные плагины, и
скилы/хуки текущего открытого проекта.


## plan / build

Два режима хода **основного** агента (`mcp_agent/agent.py`; в агентном
режиме — `pipeline_mode` — свои стадии Analyzer→Planner→Coder→Verifier, и
plan/build там не действует). Переключение: Shift+Tab или `/plan`/`/build`
в CLI, переключатель «План / Build» под полем ввода в вебе. В футере CLI
режим виден прямо в приглашении ввода — `build › ` / `plan › ` (в
агентном режиме просто `› `); в build полоски вокруг поля ввода рыжие. Режим
не сохраняется между запусками.

Чем plan отличается от build (`mcp_agent/work_mode.py`):

- **тулы**: в схеме модели только читающие (чтение/поиск/web/ask_user/skill,
  bash — всё, кроме команд, которые что-то меняют: чёрный список
  `mcp_agent/plan_bash.py` — запись в файл (`>`, `>>`, `tee`, `sed -i`),
  `rm`/`mv`/`cp`/`mkdir`…, установки пакетов, мутирующий git, `kill`,
  `docker rm/run`, `systemctl restart` и т.п., в том числе за `sudo`/`xargs`/
  `bash -c`/`$(…)`/`find -exec`; любые смотрящие команды (`ps`, `lsof`,
  `docker ps`, …) проходят; при включённом «спрашивать разрешения» каждый
  bash и так показывается в диалоге подтверждения);
  `_PlanModeMiddleware` дополнительно отклоняет всё остальное механически;
- **сабагенты**: `agent` доступен с любым типом — пишущие (`general`,
  `general-purpose`, свои с правом записи) запускаются урезанными до тех же
  читающих тулов, так что исследовать и ревьюить параллельно можно и в plan;
- **системный промпт**: в конец добавляется раздел PLAN MODE, который
  отменяет воркфлоу «правь → проверь»: модель исследует и отвечает на
  вопрос как есть. План (Goal / Context / Steps / Verification / Risks, с
  расчётом на агента, не видевшего разговор) — только если о нём просят;
- **self-heal**: вердикт «сделана ли правка» не применяется — ответом
  хода считается сам план.

Как план переходит в build: ответ plan-хода, который является планом (есть
раздел `## Steps`/`## Шаги`), сохраняется в
`<проект>/.flowai/plans/<дата>-<тема>.md` (CLI печатает путь, веб
показывает карточку с кнопкой «Выполнить план»). `/build` переключает в
build и отдаёт агенту **текущее содержимое файла** плана как задачу — файл
можно отредактировать руками перед запуском; `/build <имя файла> [уточнения]`
выполняет конкретный сохранённый план. Без свежего плана `/build` просто
переключает режим и подсказывает последний сохранённый.
